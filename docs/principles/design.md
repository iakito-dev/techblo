# UI/UX 設計原則

## 1. デザインシステム = 3層トークン

`.agents/skills/ckm-design-system` の原則を採用。

```
Primitive (raw values)
   ↓
Semantic (purpose aliases)
   ↓
Component (component-specific)
```

- ハードコード値禁止、すべて `var(--token)` 経由
- 透明度コントロールは HSL 形式
- スペーシングは 4px ベース(`--s-1` = 4px, `--s-2` = 8px ...)

パレット:
- Neutral: ウォームグレー。背景 `--color-bg-app` = `#FAFAF8`、サーフェス = 白、ホバー = `#F4F3F0`
- Primary: ink `#16181D`。ロゴ背景・プライマリボタンにのみ使用
- Accent: ティール `#0F766E`。**線と文字色のみに使用**。塗りは使わない(`accent-soft` は LP では残存だがアプリ UI では非使用、ADR-0035)
- Brand: 企業別の実ブランドカラー(カード見出しのドット・企業名に使用)
- 罫線: `--color-rule #E9E6E0`(記事間・カード上罫など)、`--color-rule-strong #D6D2C8`(見出し罫など、ADR-0035)
- 角丸: コントロール/ナビ = `rounded-sm`(10px)、カード = なし(ADR-0035 で廃止)

**実装が真実の源**: トークンは `app/globals.css` の Tailwind v4 `@theme`。
`design/mockup.html` は参考用で旧デザインのレンダリングが一部残存しており、段階的に追随させる。
ただし `@theme` 内で他の `var()` を参照しないこと(ビルド時に評価され欠落する。フォント変数は base 層で付与)。

## 2. レスポンシブ・モバイルファースト

| breakpoint | レイアウト |
|---|---|
| ~767px | セクション型ではなく、カテゴリのタブ(横スクロール・上部固定)+ 上罫カードの縦1列を無限スクロール、下部タブナビ |
| 768-1023px | 新着・棚ともコンテナクエリで1〜4列等幅(下記の列数表)、下部タブナビ |
| 1024px+ | 左サイドバー(ADR-0020)+ 新着・棚ともコンテナクエリで1〜4列等幅(最大 1680px 中央寄せ) |

- デスクトップ: 左サイドバー(ADR-0020)+ セクション型フィード(新着 + カテゴリ別6棚 + イベント・コミュニティ、ADR-0035)
- **列数(コンテンツ領域の実幅で可変。ADR-0035)**: 棚と一覧(`/?category=` など)はどちらも最大 1680px・md 以上で CSS コンテナクエリにより列数が変わる。サーバはビューポートを知らない(ADR-0019)ため、ビューポートではなくコンテンツ領域自身の幅(サイドバー等を引いた実幅)で判定する

  | コンテンツ領域の幅 | 列数 |
  |---|---|
  | 1360px 以上 | 4 |
  | 900px 以上 | 3 |
  | 600px 以上 | 2 |
  | それ未満 | 1 |

  列間 32px・行間 40px。サーバは実列数を知らないため、常に最大件数(新着12件・棚4件)を取得・描画し、CSS(`feed-latest-cutoff` / `feed-shelf-cutoff`)で実列数に満たない分(行が欠ける分)を隠す。モバイルはカテゴリのタブで切り替える縦1列のまま変わらない
- サイドバーの現在地: 左2px の teal 縦罫 + ink 太字。「カテゴリ」セクションを新設(ADR-0035)
- 下部ナビは `position: fixed`、`env(safe-area-inset-bottom)` で iOS notch 対応
- 検索は実装済み(ADR-0022)

## 3. パフォーマンス目標(Core Web Vitals)

| 指標 | 目標 |
|---|---|
| LCP | < 2.5s |
| INP | < 200ms |
| CLS | < 0.1 |

- カードはテキスト主体(OGP画像なし、ADR-0011)。画像の読込・レイアウトシフトが無いぶん LCP/CLS に有利
- 初期ペイロードは shadcn/ui の Tree shaking でslim化
- フォントは `next/font` で Inter(Latin)+ Noto Sans JP(日本語)を self-host(`display: swap`)

## 4. アクセシビリティ

- **WCAG 2.1 AA** 準拠を目標
- すべての interactive 要素に `aria-label` または可視ラベル
- フォーカスリングは `:focus-visible` で明示(`outline:none` だけは禁止)
- 色のみで情報を伝えない(アイコン併用)
- キーボードナビゲーション可能(Tab で全機能到達)

## 5. アニメーション

- **意味のあるアニメーションのみ**(装飾は控えめ)
- View Transitions API でページ遷移
- `motion/react` でステート遷移
- `prefers-reduced-motion` を尊重

## 6. AI識別の視覚表現

- AI生成コンテンツ(将来の要約等)は **必ず識別子**(✦アイコン or バッジ)を付与
- 人間が書いた説明と機械生成を視覚的に区別

## 7. 企業ブランドの扱い

- 各社のブランドカラーは **アクセント** として小さく使う(ドット・チップ・左ストライプ)
- 各社のロゴをそのまま表示しない(著作権・差別化)
- 統一されたカードフォーマットの中で出典を区別

## 8. 情報密度

- カード形式は **エンジニア向けの情報密度**(空きすぎない、詰めすぎない)
- 「メタ情報(企業名・日付)」「タイトル」「AI要約」「アクション」を1カードに同居
- カードは均一フォーマット(ヒーローカード・画像は廃止、ADR-0011)。上罫でまとまりを示し、テキスト主体の特性を強調(ADR-0035)
- 下段でフッターを下端揃えにして一覧の整列感を出す

## 9. セリフ(数字)の使い方

- Newsreader セリフ(`font-metric` utility)は数字のみ、和文には使わない
- 用例: はてなブックマーク数・ページ数カウントなど相対的な数値表現

## 10. ダーク/ライト

ダークモードは実装済み(ADR-0038)。

- 切替は next-themes が `<html>` に付ける `.dark` クラス(と HeroUI 用の `data-theme`)。既定は「システム」で、設定画面の「表示」で システム / ライト / ダーク を選ぶ
- トークン方針: **プリミティブだけ**を `app/globals.css` の `.dark` で上書きする。セマンティックトークンは `var()` 参照のまま実行時に解決されるので、コンポーネント側に `dark:` を書かない
- 新しい色は必ずセマンティックトークン経由にする(`bg-white` / `text-black` / `#xxxxxx` / `rgb()` の直書き禁止。モーダル背後は `bg-scrim`)
- 暗色パレット: 背景 `#16181D` / サーフェス `#1F2126` / 罫線 `#34363B` / 本文 `#F4F3F0`。accent のティールは暗背景でコントラストが足りないため `#34C5B0` に明るくする。ink は反転(ほぼ白)し、プライマリボタンは「明るい面 + 暗い文字」になる
- LP(`/lp`)はライト固定。ルートに `class="light" data-theme="light"` を付け、アプリと HeroUI のトークンをライトへ戻す
- 外部ファビコンなど白背景前提の画像は、薄い面 + リングの「ロゴタイル」にして暗背景でも輪郭が出るようにする

## トークン更新(ADR-0035)

セクション型フィードとエディトリアル(上罫)カードの導入に伴う変更:

- `--color-rule #E9E6E0` — 罫線(記事間・カード上罫など)
- `--color-rule-strong #D6D2C8` — 見出し罫など
- teal (accent) は線と文字色のみ、塗りは廃止
