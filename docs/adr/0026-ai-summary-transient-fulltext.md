# ADR-0026: AI記事要約は本文を取込時に一時取得して生成し、全文は保存しない

- **状態**: Accepted
- **決定日**: 2026-06-14
- **関連**: ADR-0005(部分 supersede), ADR-0010, ADR-0013, ADR-0014, ADR-0016

## 背景

ADR-0005 で「AI要約(3行サマリー)」は将来フェーズとされ、同時に「アプリ内記事リーダー(全文表示)」が**著作権配慮**で除外された。今回その将来フェーズに着手するにあたり、要件定義(`docs/features/ai-summary.md`)で次が決まった:

- 要約ソースは **本文を取得して要約**(RSS抜粋は短く精度不足のため)
- 生成は **取込時バッチで事前生成**、表示は記事ダイアログ内、形式は3行箇条書き

「本文を取得する」ことは、ADR-0005 が著作権配慮で除外した方針(全文をアプリで扱わない)と表面的に抵触する。何をどこまで許容するかを判断・記録する必要がある。

論点は2つ:
1. **本文をいつどう扱うか**(取得・保存の可否) — 著作権/ToS リスクとストレージ
2. **どこで LLM を呼ぶか** — レイヤー境界(ADR-0010: `lib/` は `features/` を import しない)

## 検討した選択肢

### A. RSS抜粋のみで要約(本文を一切取得しない)

- ADR-0005 の方針を完全踏襲、リスクゼロ
- ✗ 抜粋が数十文字の企業も多く、要約品質が「抜粋の言い換え」に留まる
- ✗ 要件で否決済み

### B. 本文を取得し、全文をDBに保存して要約(随時再利用)

- 再生成・別用途(検索/タグ分類)に流用しやすい
- ✗ **全文の永続保存は著作権上もっともリスクが高い**(複製物の保持)
- ✗ ストレージ増。ADR-0005 の除外理由に正面から反する

### C. 本文を取込時に一時取得 → 要約/表示用タグ生成 → 本文は破棄(派生物のみ保存)【採用】

- LLM に渡すために**一時的に**本文を取得し、生成後はメモリ上から破棄。永続化するのは AI が生成した3行要約と表示用タグ(派生物)のみ
- robots.txt を尊重し、不許可ドメインは RSS 抜粋フォールバックに切り替える
- 要約には AI 生成ラベルと元記事への出典リンクを必ず添える
- △ 本文取得の実装・失敗ハンドリングが必要

### LLM 呼び出し位置(直交する判断)

- LLM クライアントは横断 infrastructure として `lib/ai/` に置き、`application` の usecase へ**注入**する。`lib/` は `features/` を import しない原則(ADR-0010)を維持。本文取得(fetcher + 本文抽出)も `lib/` または `features/ai-summary/infrastructure/` に置き、usecase からポートとして利用する。

## 決定

**C を採用**。本文は取込時に一時取得するだけで永続保存せず、保存対象は AI が生成した3行要約と表示用タグに限定する。

ガードレール:

- **全文は保存しない**(DB・ログ・キャッシュいずれにも残さない)。`article_summaries.bullets` に3行、`article_summaries.tags` に表示用タグのみ保存。
- **robots.txt / ToS 尊重**: クロール不許可ドメインは本文取得をスキップし RSS 抜粋にフォールバック。User-Agent を明示し、取得はレート制限する。
- **出典明記**: ダイアログの要約セクションに「AIが元記事を要約したもの・正確性は無保証」ラベルと元記事リンクを常時表示。
- **入力上限**: 本文は先頭 N トークン相当で打ち切ってからプロンプトへ(コスト上限)。
- **出力検証**: LLM 応答は Zod で「bullets は string[] 長さ1〜3」「tags は string[] 長さ0〜5」を検証、逸脱は `status=failed`。
- **タグの用途限定**: `tags` は記事ダイアログ上の表示補助であり、検索・分類・集計に使う正規化タグではない。
- **プロバイダ非依存**: LLM 呼び出しは `application` 層のポート(インターフェース)越しに行い、具体実装(Claude / Gemini 等)は `lib/ai/` のアダプタに隔離する。ベンダーを後から差し替え可能にする(実測コスト差が小さく、品質比較で確定したいため)。`article_summaries.model` に使用モデルを記録。
- **初期モデル**: 実測ボリューム(下記)ではコストがどのモデルでも誤差のため、料金ではなく日本語3行要約の品質で選ぶ。**最安ティア(Gemini Flash-Lite 系 もしくは `claude-haiku-4-5`)を起点**にサンプル20〜30記事で実出力を比較して確定する。品質不足時のみ上位ティアへ。
- **バッチ割引**: 取込時生成はレイテンシ非依存のため Batches API(50%オフ相当)を使う。
- **レイヤー**: LLM/本文取得は infrastructure(`lib/ai/` 等)、生成オーケストレーションは `features/ai-summary/application`、表示は記事ダイアログへ slot 注入(feed は ai-summary を import しない / ADR-0013)。

### 実測コスト(本番DB, 2026-06-14 集計)

27社・総記事 892件・直近30日の公開 272件・`description` 平均5,636字。1記事 ≈ 6,000入力 + 150出力トークン想定:

| モデル(Batch 50%) | 月額(272本) | バックフィル(892件・1回) |
|---|---|---|
| Gemini Flash-Lite 系 | ≈ $0.06 | ≈ $0.2 |
| `claude-haiku-4-5` | ≈ $0.9 | ≈ $3.0 |
| `claude-sonnet-4-6` | ≈ $2.8 | ≈ $9 |

→ 月額は最大でも数百円、バックフィルも1回 ¥500〜¥1,300 程度。**コストは選定の決め手にならない**ことを確認済み。Classmethod 等の大量投稿フィードは実データ上は存在せず(直近30日トップは serverworks 65本)、外れ値対策は不要。

これにより ADR-0005 の「AI要約=将来」「全文取得=除外」のうち、**全文取得除外を「一時取得・非保存」の範囲で部分的に supersede** する。アプリ内全文リーダー(ユーザーへ全文を再配信する)の除外は維持する。

## 結果

- ✅ RSS抜粋より高品質な3行要約を提供できる(機能の差別化要素を回復)
- ✅ 全文を保存しないため著作権・ストレージ両面のリスクを最小化
- ✅ モデル ID を記録し将来のモデル移行・再生成に対応
- ⚠️ 本文取得の失敗(404・JS依存・robots不許可)へのフォールバック設計が必須
- ⚠️ 取込ごとに LLM コストが先行発生(レート上限・人気記事優先などのコスト管理が必要)
- ❌ 本文を保存しないため、要約以外の用途(全文検索・タグ分類)へは流用できない(別途取得が必要)
