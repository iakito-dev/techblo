# ADR-0005: MVPから除外する機能の明確化

- **状態**: Accepted
- **決定日**: 2026-05-28

## 背景

機能のスコープを定義せずに作り始めると、終わらないプロジェクトになりがち。MVPでリリースする範囲と、明示的に「将来」とした範囲を文書化する必要があった。

## 検討した選択肢

### A. 機能を増やしすぎる(全部入りMVP)

- リリースまで時間がかかる
- 個人開発では完成しないリスク

### B. 最小限のMVP(コア機能のみ)

- 早期リリース可能
- ユーザーフィードバックを元に拡張
- 一部の魅力的機能を諦める判断が必要

### C. ハイブリッド(優先度を明示)

- MVP範囲を厳格に決め、その他は明示的に「将来」と記録
- 後で迷わない

## 決定

**C. MVPスコープと将来機能を明示的に分離**。

### MVP に含める(P0+P1)

- 記事一覧表示(カード形式・新着順)
- OGP画像 + タイトル + RSS抜粋表示
- 外部リンクで元ブログへ遷移
- Google OAuth ログイン
- ブックマーク、お気に入り(2階層)
- 購読企業ON/OFF
- レスポンシブ(モバイル/PC)

### MVP から除外

| 機能 | 理由 |
|---|---|
| **AI要約** | コスト・実装工数を抑える。RSS抜粋で代替 |
| **企業追加(ユーザー操作)** | 開発者がDBで管理、ユーザーUIは不要 |
| **Anthropic/OpenAI等の海外AI企業** | 公式RSSなし、スクレイピング工数 |
| **タグ/カテゴリフィルタ** | 各社の記事タグが不統一、自動分類が別途必要 |
| **全文検索** | DB全文検索の実装コスト |
| **新着通知** | 必要性が見えてから |
| **アプリ内記事リーダー(全文表示)** | 著作権配慮、外部リンクで十分 |
| **コメント/SNS機能** | スコープ外 |
| **ネイティブアプリ** | レスポンシブWebで対応 |
| **ダークモード切替** | ライトテーマで統一(将来追加可) |

### 将来フェーズ

- AI要約(3行サマリー)
- 海外AI企業対応(スクレイピングまたはRSSHub経由)
- タグ/カテゴリの自動付与(LLMで分類)
- 全文検索
- 新着通知
- 著者単位/タグ単位のフィルタ
- 共有用URL(個別記事ページ)
- 読了マーク
- ダークモード

## 結果

- ✅ MVP完成まで最短ルート
- ✅ 議論を蒸し返さない(「これは将来」で打ち切れる)
- ⚠️ AI要約抜きでローンチするため、当初の差別化要素が減る
- ❌ ユーザーから「タグ検索したい」等の要望は出る可能性
