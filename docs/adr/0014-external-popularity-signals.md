# ADR-0014: 人気順に外部シグナル(はてなブックマーク数)を採用

- **状態**: Accepted
- **決定日**: 2026-06-03
- **関連**: ADR-0009(データモデル), ADR-0013(オフセットページングとフィードキャッシュ)

## 背景

人気順は当初、内部シグナルのみで算出していた:

```
score = view_count * 1 + bookmark_count * 2 + favorite_count * 3
```

しかし本サービスはユーザー数が少なく、view / bookmark / favorite がほぼ 0 に張り付くため、
人気順が実質的に機能していなかった(新着順とほぼ同じ並びか、ノイズになる)。

「記事の盛り上がり」を表すには外部シグナルの取り込みが必要だが、取得可能性は媒体によって大きく異なる:

- 元ページの生PV数 → 自社ホスティングのブログが多く、ほぼ非公開
- X(旧Twitter)シェア数 → API 有料化で実質取得不可
- はてなブックマーク数 → 公開API・認証不要・一括取得可。日本のテック記事における事実上の人気指標

## 検討した選択肢

### A. 内部シグナルのみ(現状維持)

- メリット: 追加実装なし
- デメリット: ユーザーが少ない間は機能しない。本質的な問題が解決しない

### B. はてなブックマーク数を主シグナルにする

- 内容: はてな公開API(`/count/entries`、50件一括)で直近記事のブックマーク数を取得し、重み付けに加える
- メリット: 読者層と完全に一致。API が無料・無認証・一括対応で実装が軽い
- デメリット: はてな非対象の媒体は外部シグナルが付かない。再取得のタイミング設計が要る

### C. プラットフォーム別API(Qiita/Zenn のいいね等)も追加

- メリット: クロス投稿している記事はより精度が上がる
- デメリット: 企業の公式ブログは自社ドメインが主で効果が限定的。媒体ごとの実装コストが増える

## 決定

**B を採用**。はてなブックマーク数を人気スコアの主成分(重み 4)とし、時間減衰を掛ける:

```
score = (view*1 + bookmark*2 + favorite*3 + hatena*4 + 1) / (経過時間[h] + 2)^1.5
```

- 重み・gravity の唯一の定義は `features/feed/domain/popularity.ts`。infrastructure の SQL もこの定数を参照する
- 時間減衰(Hacker News 風の重力モデル、gravity=1.5)で「最近 + 伸びている」記事を上位に出す
- 取得は Trigger.dev の定期タスクに集約する。RSS 取り込み後に直近30日の記事のはてブ数を再取得して上書きする。取得失敗は更新全体を止めない(非致命)
- C は将来の拡張余地として見送り

## 結果

- ✅ ユーザーが少なくても人気順が機能する(外部の盛り上がりを反映)
- ✅ 時間減衰により古い殿堂記事が居座らず、フィードが「今」を映す
- ✅ API が無料・無認証で運用コストが低い
- ⚠️ はてブは公開後数日かけて伸びるため、1回の取得では不十分。「更新」のたびに直近記事を再取得して追従する(将来は cron 化も検討)
- ⚠️ 時間減衰は `now()` 依存のため式インデックスが張れない。現データ規模(数百件)では `ORDER BY` の都度計算で許容
- ❌ はてな非対象の媒体には外部シグナルが付かない(内部シグナルのみで評価)

## 追補: 集計期間つき人気順

全期間の減衰スコアに加え、人気順に集計期間(`?period=today|week|month|all`)を導入した。

- `all`(既定): 上記の時間減衰スコア(= 単純な人気順)
- `today/week/month`: 直近 1/7/30 日に**公開された**記事に絞り、減衰なしの生スコア
  (`view*1 + bookmark*2 + favorite*3 + hatena*4`)で並べる。期間でウィンドウを切るため減衰は外す
- 期間は直近 N 日のローリングウィンドウ(カレンダー境界ではない)。実装の単純さと「直近の盛り上がり」という意味を優先
- 期間は対象集合を絞るので `count`(ページ数算出)も同じフィルタで数える
- 実装: `domain/feed-sort.ts`(`PopularPeriod` / `parsePeriod`), `infrastructure/drizzle-article-repository.ts`(`RAW_SCORE` / `DECAYED_SCORE` と期間ウィンドウ), `web/components/sort-control.tsx`(期間タブ)
