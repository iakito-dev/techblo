# ADR-0027: AI生成の表示タグを固定キュレーションのタグ絞り込みに流用する

- **状態**: Accepted
- **決定日**: 2026-06-15
- **関連**: ADR-0026(一部方針を更新), ADR-0010, ADR-0013, ADR-0022

## 背景

ADR-0026 で導入した AI 要約は、3行要約に加えて「表示用の関連タグ(最大5件)」を `article_summaries.tags`(jsonb の `string[]`)に永続化している。ADR-0026 はこのタグを **「記事ダイアログ上の表示補助であり、検索・分類・集計に使う正規化タグではない」** と明記していた。

その後、これらのタグを記事カードにも表示するようにした(同タグでトピックを把握できる)。続けて「タグでフィードを絞り込みたい(デスクトップ)」という要望が出た。タグは正規化されておらず(`AI` / `生成AI` / `LLM` が別物)、自由記述で表記ゆれがある。これを検索手段に流用してよいか、流用するならどう破綻を抑えるかを判断・記録する。

論点:

1. **タグを絞り込みに使ってよいか**(ADR-0026 の「検索用途に使わない」との整合)
2. **絞り込み条件をどこで組むか**(タグは ai-summary 所有・別テーブル。レイヤー境界 ADR-0010)
3. **絞り込みの入口(どのタグを見せるか)** — 自由記述タグは候補が発散する

## 検討した選択肢

### A. 正規化タグ基盤を新設してから絞り込む

- タグ用の正規語彙テーブル + 記事への付与を別 feature で持つ
- メリット: 表記ゆれが無く検索品質が高い
- デメリット: 重い。今回の「とりあえずデスクトップで絞れれば良い」に対して過剰

### B. 表示タグをそのまま完全一致で絞り込む + 入口は固定キュレーション【採用】

- `article_summaries.tags` を `@>`(jsonb 包含)で完全一致フィルタ。`?tag=` の URL 駆動(企業フィルタ `?company=` と同じ流儀)
- 絞り込みの入口は**サイドバーの固定キュレーション**(需要の高い代表キーワードを手動で並べる)。自由記述タグの発散をここで抑える
- 絞り込み SQL は feed の Repository が `article_summaries` を EXISTS で参照して組む(既存の並び替え/ページングをそのまま活かす)
- メリット: 最小実装。既存のフィルタ配管(`?company` と同型)に乗る。1クエリで完結
- デメリット: 表記ゆれを取りこぼす(`生成AI` で絞ると `AI` 単独タグの記事は出ない)。キュレーション外のタグは絞れない

### C. ai-summary 側でタグ→記事 id を引き、feed に id 群を渡す

- メリット: feed が ai-summary のテーブルを参照しない(境界が綺麗)
- デメリット: 一致記事が多いと id 群が膨れページング/並びが破綻。非効率

## 決定

**B を採用**。表示タグを完全一致のフィルタにそのまま流用し、入口はサイドバーの固定キュレーションに限定する。これは ADR-0026 の「タグは正規化検索用途ではない」を**否定はしない**: 依然として正規化タグ基盤は持たず、表示タグを「ゆるい絞り込みの取っ掛かり」として割り切って使う(検索の主経路は引き続き ILIKE 全文検索 `?q=`・ADR-0022)。

レイヤーは ADR-0013 の横断合成に従う: タグ列は ai-summary の所有だが、`db/schema` は共有インフラなので feed の Repository から参照してよい(既に `companies` / `reads` を参照しているのと同じ)。タグはドメイン層へ `string` として渡し、スキーマ構造は漏らさない。

スコープは**デスクトップ(サイドバー)のみ**。モバイル UI・カードチップのクリック導線・複数タグ AND/OR は今回入れない。

## 結果

- ✅ 既存のフィルタ配管(`?company` と同型・`?tag=` URL 駆動)に乗り、最小差分でデスクトップのタグ絞り込みが入る
- ✅ 公開フィードのキャッシュ(`getFeed`、'use cache')はキュレーションタグの少数有界バリアントなので、そのままキーに乗ってウォームを保てる
- ⚠️ タグ列は ai-summary 所有だが feed Repository が EXISTS で参照する。境界上はコメントで明示し、参照は read-only に限定
- ⚠️ 新着記事のタグは要約生成バッチ完了後に付くため、フィードキャッシュ(取込で無効化)とのタイミング差で反映が最大数分遅れうる
- ❌ 表記ゆれは取りこぼす(`AI`/`生成AI`/`LLM` は別物扱い)。検索の網羅性は ILIKE 全文検索(`?q=`)が担い、タグは補助に留める
- ❌ 絞り込めるのは固定キュレーションのタグのみ(任意タグでの絞り込みは不可)
