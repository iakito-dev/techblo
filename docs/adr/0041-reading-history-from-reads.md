# ADR-0041: 閲覧履歴(/history)を既読テーブルの readAt から提供する

- **状態**: Accepted
- **決定日**: 2026-10-19
- **関連**: ADR-0017, ADR-0021, ADR-0036

## 背景

記事ページ(`/a/[id]`)を開くと既読が記録される(ADR-0021)が、記録はフィードの未読/既読フィルタにしか使われていない。「さっき読んだあの記事」を探し直す手段が無く、保存し忘れた記事にはたどり着けない。

`reads` には `readAt` があるので、スキーマ変更なしで「最近読んだ記事」を出せる。ただし既読化は `onConflictDoNothing` で、再訪しても `readAt` は初回のまま。また既読は全記事に及びうるため、全件一覧は持たない方針(ADR-0021)。

## 検討した選択肢

### A. `reads.readAt` を「最後に開いた時刻」に変え、直近 N 件を出す

- 再閲覧時は `onConflictDoUpdate` で `readAt = now()` に進める
- メリット: スキーマ変更なし。「最近読んだ順」が実際の閲覧と一致する
- デメリット: 再閲覧のたびに UPDATE が1回走る(従来は no-op)

### B. 閲覧ログ用の別テーブル(閲覧ごとに1行)

- メリット: 閲覧回数や時系列を完全に残せる
- デメリット: マイグレーションと行数増加。履歴一覧の用途に対して過剰

### C. `readAt` は初回のまま、初回既読順に出す

- メリット: 書き込みは変わらない
- デメリット: 何度も見返す記事が履歴の下に沈み、「最近読んだ」にならない

## 決定

A を採用する。

- `ReadRepository.markRead` は再閲覧時に `readAt` を更新する。`addMany`(ゲスト移行)は従来どおり `onConflictDoNothing`(移行で DB 側の時刻を上書きしない)
- `ReadRepository.listRecent(userId, limit)` で `readAt` 降順の直近 100 件(`READ_HISTORY_LIMIT`)を返す。全件一覧は持たない方針(ADR-0021)は維持する
- 履歴クエリ(`getRecentReads`)は `'use cache'` しない。`markReadAction` は `userReads` を `revalidateTag(…, 'max')`(stale-while-revalidate)で無効化するので、キャッシュすると今読んだ記事が次の表示に出ない。単一ユーザー・件数上限付きなので毎回引いても軽い
- 索引は追加しない。`reads_user_article_uq (userId, articleId)` で userId に絞った後のソートになるが、1ユーザーの既読件数規模なら許容できる
- 表示は JST の暦日ごとにまとめる(今日 / 昨日 / M月D日(曜))。サーバー・ブラウザのタイムゾーンに依らず揃える
- ゲスト(ADR-0017): localStorage の既読 ID は時刻を持たないので、`addGuestSave('read')` で再閲覧の ID を末尾へ移し、配列順を「最後に開いた順」にする。履歴は末尾 100 件を新しい順に出し、日付見出しは付けない
- 導線: デスクトップはサイドバーの「ライブラリ」、モバイルは設定メニューの行(下部タブは4枠のまま増やさない)、キーボードは `g r`

## 結果

- ✅ スキーマ変更なしで「最近読んだ記事」を見返せる
- ✅ 保存し忘れた記事も履歴から「あとで読む / お気に入り」に保存できる
- ⚠️ 既読記事を開くたびに UPDATE が1回走る(従来は no-op)
- ⚠️ 1ユーザーの既読が大きく増えたら `(userId, readAt)` 索引の追加を検討する
- ❌ 履歴から個別に消す操作は無い(既読を外す操作が無いため。ADR-0021)
