# ADR-0047: UI を変える PR に変更前後のスクリーンショットを付ける

- **状態**: Accepted
- **決定日**: 2026-11-07
- **関連**: ADR-0045, ADR-0046

## 背景

ファクトリー(ADR-0045 / 0046)は、好みが割れる見た目の変更を人のレビューに回す。ところが PR には文章の説明しかなく、オーナーは画面を見ないとマージを判断できなかった。
判断待ちの PR が上限(3 本)に溜まったまま 10 日近く動かず、その間ファクトリーは自動マージできる作業(主にテスト追加)しか出せなくなった。

## 検討した選択肢

### A. Vercel の Preview デプロイを見てもらう

- PR ごとに Preview URL が付いており、追加の仕組みは要らない
- 変更前と並べて見られない。スマホで PR を見ながら判断しにくい
- エージェント環境からは Preview に届かず、エージェントが自分で確かめられない

### B. Storybook でコンポーネント単位に見る

- 状態ごとの見え方を網羅でき、Chromatic 等で差分も取れる
- 新しい依存・設定・ストーリーの保守が要る。ページ単位の崩れ(余白・並び)は見えにくい

### C. サンドボックスで変更前後を撮り、PR に比較表を貼る(採用)

- ADR-0046 のサンドボックス(`scripts/sandbox.sh`)をそのまま使い、Playwright で同じ条件の 2 枚を撮る
- 画像は main と履歴を共有しない専用ブランチ `factory-screenshots` に置き、PR 本文に Before / After の表で貼る
- 依存の追加はない(Playwright はクラウド環境にグローバルで入っている)

## 決定

**C** を採用する。Vercel の Preview は、実データでの確認用にこれまでどおり併用する。

- `scripts/pr-shots.cjs`: 指定ページをモバイル / デスクトップ(必要ならダークも)で撮る
- `scripts/pr-shots-publish.sh`: 画像を `factory-screenshots/pr-<番号>/` に push し、比較表の Markdown を出す
- `factory` スキル: UI を変える PR には比較表を必須にする。表のない UI の PR は出さない

## 結果

- ✅ オーナーが PR の画面だけで見た目の変更を判断できる
- ✅ エージェント自身も、撮った画像で変化が写っているかを確かめられる
- ⚠️ デモ記事での見え方であり、企業アイコンなど外部画像は写らない。実データでの確認は Preview で行う
- ⚠️ `factory-screenshots` ブランチに画像が溜まり続ける。重くなったら古い PR の分を消す
- ❌ コンポーネント単位の網羅的な確認(Storybook のような)は得られない
