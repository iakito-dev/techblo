# ADR-0036: 記事詳細をダイアログから個別ページへ

- **状態**: Accepted
- **決定日**: 2026-09-15
- **関連**: ADR-0011, ADR-0013, ADR-0019, ADR-0021, ADR-0026, ADR-0029, ADR-0035
- **Supersedes**: なし(ADR-0023 のシート挙動のうち、記事プレビュー用シートの部分だけが不要になる)

## 背景

記事カードのタイトルを押すと、デスクトップは右のサイドパネル、モバイルは下から出るボトムシート(vaul)でプレビューを開いていた。一方で共有リンクの着地先として記事ページ `/a/[id]` は既に存在し(ADR-0029)、**同じ内容を2箇所で実装**していた。

運用してみて次の問題が出た:

- **戻る操作が独自実装**: シートは `history.pushState` を自前で積み、`popstate` で閉じる。ブラウザの戻る/進む・iOS のスワイプバックと噛み合わせるためのコードが増え続けていた
- **共有が一段遠い**: 開いている記事の URL がアドレスバーに出ないので、共有はシート内の共有ボタン経由でしか行えない
- **同じ画面が2実装**: ダイアログと `/a/[id]` に同じ「メタ + 画像 + AI要約 + 抜粋 + 元記事ボタン」があり、変更のたびに両方を直す必要があった
- **初期バンドル**: ダイアログは遅延読み込みしていたが、開いた瞬間に vaul + motion のチャンクを取りに行くため、最初の1回は待ちが入る

## 検討した選択肢

### A. ダイアログを維持し、URL 同期を足す(不採用)

- シートの開閉を `/a/[id]` の URL 変更と同期させる(いわゆる intercepting routes / モーダルルート)
- メリット: 一覧が背後に残る体験を維持できる
- デメリット:
  - Next の intercepting routes は「一覧を保持したままのモーダル」と「直リンクのフルページ」の2系統を持つことになり、実装は減らずむしろ増える
  - 戻る操作の独自実装は消えない(シートのドラッグと履歴の整合は引き続き自前)

### B. 個別ページへ遷移する【採用】

- カード/イベント行のタイトルを `/a/[id]` への `next/link` にし、詳細はページとして開く(X / Threads と同じ形)
- メリット:
  - 戻る・進む・スワイプバック・新規タブ・URL 共有がすべてブラウザ標準のまま働く。独自の履歴操作が不要
  - 実装が `/a/[id]` の1箇所に集約される(ダイアログ約 300 行と vaul 依存の起動経路を削除)
  - 一覧の初期バンドルからダイアログのチャンクが消える
- デメリット:
  - 一覧の文脈(背後に見えるカード)が失われる
  - 遷移のたびにページを取得するため、素朴に実装すると「一覧 → 白 → 記事」のチラつきが出る(後述の対策で潰す)

## 決定

B を採用する。記事詳細は `/a/[id]` の**ページ遷移**で開く。

### 遷移とチラつき対策

「押した瞬間に枠が出て、位置が動かないまま中身が埋まる」ことを条件にする。

1. **シェルを保持する**: `app/a/[id]` を `app/(app)/a/[id]` へ移し、Header / Sidebar / MobileNav を `(app)/layout.tsx` から受ける。URL は変わらない。遷移で差し替わるのはコンテンツ領域だけになり、サイドバーの企業一覧やヘッダーのアバターが再取得・点滅しない
2. **静的シェルを先読みする**: 記事本体(`loadArticle`)と AI要約(`getSummaryByArticleId`)はユーザーに依存せず `'use cache'` なので、ページは PPR(`◐`)としてプリレンダされる。カードの `Link` は既定の prefetch(ビューポートに入ったカードだけ)でこのシェルを取っておく
3. **ユーザー依存部分を隔離する**: 保存状態(ブックマーク/お気に入り)だけが session 依存なので `ArticleDetailActions` として別の Suspense 境界に閉じ、本文の表示を待たせない
4. **skeleton を実レイアウトに合わせる**: `loading.tsx` と本文の Suspense fallback は同じ `ArticleDetailSkeleton` を使い、タイトル行・画像枠・要約ブロック・フッターを実物と同じ位置と高さで置く
5. **戻りを即時にする**: 戻る導線は `router.back()`。一覧はクライアントルーターキャッシュ(`staleTimes.dynamic = 30`)から復帰し、スクロール位置はブラウザの復元に任せる。`Link` で `/` へ進めると新しい履歴エントリになり一覧の先頭に戻ってしまうため、back を使う

`generateStaticParams` で記事ページを事前生成すればさらに速くなるが、**ビルド時に DB クエリを実行しない**既存契約(ADR-0016 / `ci.yml`、Sidebar の `connection()` と同じ理由)を崩すため採らない。

### 計測と既読マーク

表示回数の加算(`trackArticleView`)と既読マーク(ADR-0021)は、カードのクリックハンドラではなく**着地したページ側**(`ArticleViewTracker`)で行う。クリック直後に Server Action を投げると遷移でリクエストが中断されうるのに対し、着地後なら確実に届く。ゲスト判定はクライアントの `useSession()` で行う(サーバーで session を読むとページ本体が動的になり、prefetch できる静的シェルが無くなるため)。

### 削除するもの

- `features/feed/web/components/article-dialog.tsx`(サイドパネル / ボトムシート両方)
- `features/feed/web/components/lazy-article-dialog.tsx`
- `features/feed/web/components/use-article-dialog-trigger.ts`
- `components/article/article-summary.tsx`(ダイアログの `summary` スロット専用だった)
- `ArticleCard` の `summary` / `onOpen` props

`vaul` は絞り込みシート(`feed-bottom-sheet.tsx`)が、`motion` は LP が引き続き使うため依存は残す。

## 結果

- ✅ 戻る/進む・スワイプバック・新規タブ・URL 共有がブラウザ標準の挙動になり、履歴の独自操作が不要になった
- ✅ 詳細の実装が `/a/[id]` に一本化され、共有リンクの着地先と一覧からの遷移先が同じ画面になった
- ✅ 一覧の初期バンドルからダイアログ(+ vaul)の起動経路が消えた
- ⚠️ 一覧が背後に残る「マスター詳細」の体験は失われる。デスクトップの広い画面では情報量が減るため、必要なら将来サイドパネルを**別の判断として**再導入する
- ⚠️ 動的セグメントを持つルートを `(app)` 配下に入れたため、`usePathname()` を使うシェル(Header / MobileNav / MobileSwipeNavigation)を Suspense 境界に入れる必要が生じた(cacheComponents の `CLIENT_HOOK_DYNAMIC`)。静的ルートは従来どおりプリレンダに入り、記事ページだけがシェルを後からストリームする
