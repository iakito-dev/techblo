# ADR-0032: タグ絞り込みを類義語グループ化 + 人気ベースの固定キュレーションにする

- **状態**: Accepted
- **決定日**: 2026-06-19
- **関連**: ADR-0027(本ADRで一部方針を更新), ADR-0026, ADR-0022, ADR-0010, ADR-0013

## 背景

ADR-0027 で「AI生成の表示タグ(`article_summaries.tags`)を完全一致(`@>`)で絞り込み、入口はサイドバーの固定キュレーション」を採用した。運用後、実データ(`article_summaries.tags` の出現頻度)を見ると2点の課題が出た。

1. **入口が重複的で発散している**: 旧キュレーション12件は `AI` / `生成AI` / `LLM` / `機械学習` が別エントリで並び、AI系だけで4枠を消費していた。`AI` 単独の完全一致は 47 件だが、これらは実質同じトピックで、ユーザーから見ると「どれを押せばいいか」が分かりにくい。
2. **人気タグが載っていない**: 実データ上位の `Kubernetes`(44)/ `Terraform`(42)/ `QA`(46)/ `iOS`(36)/ `Rails`(26) などが旧リストに無く、逆に相対的に頻度の低い `Google Cloud`(20)は載っていた。

完全一致のままだと「正規化されていないので `生成AI` で絞ると `AI` 単独タグの記事が出ない」という ADR-0027 が受け入れていたトレードオフが、入口の見え方とも噛み合っていなかった。

## 検討した選択肢

### A. 正規化タグ基盤を新設する

- タグの正規語彙テーブル + 記事への付与を別 feature で持つ(ADR-0027 の選択肢Aの再掲)
- メリット: 検索品質が高い
- デメリット: 依然として重い。今回の課題(入口の整理)に対して過剰

### B. canonical ラベル + 類義語グループを固定キュレーションで持つ【採用】

- キュレーションを `{ label, aliases }` の配列にし、`label`(canonical = サイドバー表示 兼 `?tag=` 値)に複数の生タグ(`aliases`)を束ねる
- 絞り込みは `aliases` の各タグに対する `@>` 包含判定を **OR**(= jsonb `?|` 相当。各項とも `tags` の GIN が効く)
- 単一の真実源を `lib/tags/curated.ts` に置き、サイドバー(web)と Repository(infrastructure)の双方が参照する
- 件数選定は実データの出現頻度に基づき、人気上位 18 件を採用
- メリット: 入口の重複が消え(AI系→`AI・LLM` 1枠)、人気タグを網羅できる。完全一致の OR なのでインデックスはそのまま効く。パイプラインの `tag: string`(canonical)型は不変で差分が最小
- デメリット: 依然として正規化検索基盤ではない。キュレーション外のタグ・グループ外の表記ゆれは取りこぼす

### C. ai-summary 側でタグ正規化マップを持ち、feed に展開済みタグ群を渡す

- メリット: feed が展開ロジックを持たない
- デメリット: キュレーションは「どのタグをどう見せるか」という表示・需要の話で ai-summary のドメイン関心ではない。所有が不自然

## 決定

**B を採用**。ADR-0027 の「完全一致・固定キュレーション」という骨格は維持しつつ、(1) キュレーションを canonical + 類義語グループに拡張し、(2) 絞り込みを類義語の OR 包含に、(3) 選定を実データの人気ベースにする。

`lib/tags/curated.ts` を単一の真実源とする。これは ADR-0013 の「`db/schema` 等の共有インフラは層をまたいで参照してよい」と同じ位置づけで、`lib/tags` は表示・絞り込み双方が依存するキュレーション設定の共有モジュールとして扱う(`expandTag(canonical): string[]` を Repository が呼ぶ)。`depcruise` で違反が出ないことを確認済み。

引き続き正規化タグ基盤は持たず、検索の主経路は ILIKE 全文検索(`?q=`・ADR-0022)が担う。スコープはデスクトップ(サイドバー)のみで、カードチップ導線・複数タグ AND/OR は今回も入れない。

## 結果

- ✅ AI系が `AI・LLM` 1エントリに集約され、サイドバーの重複が解消。`AI・LLM` の一致記事は 47 → 405 件に増えた(`生成AI`/`AI`/`LLM`/`機械学習` の和集合・重複排除済み実測)
- ✅ 人気タグ(`Kubernetes`/`Terraform`/`テスト`(QA含む)/`iOS`(Swift含む)/`Ruby`(Rails含む)等)を網羅。キュレーションは12→18件
- ✅ パイプラインの `tag: string`(canonical)は不変。差分は `lib/tags/curated.ts` 新設 + サイドバー描画 + Repository の絞り込み SQL のみ
- ✅ 完全一致の OR(`@>` × N)なので `tags` の GIN インデックスはそのまま効く。公開フィードキャッシュ(`getFeed`)も canonical をキーに持つ少数有界バリアントのままウォームを保つ
- ⚠️ `lib/tags` を infrastructure(Repository)から参照する。共有インフラ扱いの境界はコメントで明示し、参照は read-only に限定
- ❌ 正規化検索基盤ではない。グループに入れていない表記ゆれ・キュレーション外のタグは引き続き取りこぼす(網羅は `?q=` が担う)
