# ADR-0049: 閲覧履歴から記事を削除できるようにする(既読を外す唯一の操作)

- **状態**: Proposed
- **決定日**: 2026-11-20
- **関連**: ADR-0021(既読管理), ADR-0041(閲覧履歴), ADR-0017(ゲスト保存)

## 背景

ADR-0021 では既読を「記事ページを開いたら付くだけで、外す操作は無い」とした。その後 ADR-0041 で既読の `readAt` から閲覧履歴(`/history`)を作ったため、既読は「未読/既読フィルタの材料」に加えて「人に見える履歴」にもなった。

その結果、次のことができない:

- 誤って開いた記事・人に見られたくない記事を履歴から消す(ゲストは localStorage、ログイン時は DB に残り続ける)
- 開いただけでちゃんと読んでいない記事を、未読フィルタに戻す

閲覧履歴を持つ一般的なサービス(ブラウザ・動画サービス等)は、履歴の個別削除を備えている。

## 検討した選択肢

### A. 現状維持(外す操作は無し)

- 実装・概念が最小
- 履歴に残したくない記事を消す手段が無い。履歴を見せる画面を作った以上、プライバシー上の不満になりやすい

### B. 閲覧履歴のカードに「閲覧履歴から削除」を置き、既読の行を消す(採用)

- 履歴と既読は同じ `reads` の行なので、履歴から消す = 既読を外す(未読フィルタに戻る)
- 外す操作は閲覧履歴の画面だけに置く。フィードのカードに既読トグルは置かない(ADR-0021 の「カードを既読で飾らない・手動トグル無し」は維持)

### C. 既読と履歴を別テーブルに分け、履歴だけ消せるようにする

- 「履歴は消すが既読は残す」ができる
- スキーマ変更と二重書き込みが必要。分ける需要が見えていない

## 決定

**B** を採用する。

- `ReadRepository.remove(userId, articleId)` を足し、`reads` の行を消す(冪等)
- ログイン時は `removeReadAction`(UUID 以外は VALIDATION、未ログインは UNAUTHORIZED)。`userReads` タグは `markReadAction` と同じく遅延無効化
- ゲストは localStorage の既読 ID から外す(`setGuestSave('read', id, false)`)
- 画面は楽観的に一覧から消し、失敗したら戻してトーストを出す。元に戻す(Undo)は付けない(既読を付け直すと `readAt` が今になり、履歴の並び位置が変わってしまうため)

## 結果

- ✅ 閲覧履歴から個別に記事を消せる。消した記事は未読フィルタに戻る
- ✅ スキーマ変更なし(既存の `reads` 行の削除だけ)
- ⚠️ 「既読は外さない」前提(ADR-0021)が閲覧履歴の画面に限って崩れる。フィードのカードからは今も外せない
- ⚠️ 一括削除(履歴をすべて消す)は今回は入れない。需要が見えたら同じ `remove` 系の拡張で足す
